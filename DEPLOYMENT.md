# Deploying SignalLoop

SignalLoop is two pieces:

| Piece    | What it is                                          | Where it runs                    |
| -------- | --------------------------------------------------- | -------------------------------- |
| Frontend | Plain HTML/CSS/JS (`index.html`, `src/`, `assets/`) | Freebuff Sites (static assets)   |
| Backend  | Flask + PostgreSQL API (`backend/`)                 | Any Python host (Render, Railway, Fly.io, a VM) |

The site never talks to the API cross-origin: `worker.js` proxies every `/api/*`
request to the backend, so the browser stays same-origin and **no CORS
configuration is needed** in the normal setup.

---

## 1. Backend (Flask + PostgreSQL)

### Environment variables

Copy `backend/.env.example` to `backend/.env` locally; set these as real
environment variables on your host.

| Variable                             | Required | Notes                                                                          |
| ------------------------------------ | -------- | ------------------------------------------------------------------------------ |
| `FLASK_APP`                          | yes      | `run.py`                                                                       |
| `SECRET_KEY`                         | yes      | Long random value. **The app refuses to start in production with placeholders.** |
| `JWT_SECRET_KEY`                     | yes      | A *different* long random value.                                                |
| `DATABASE_URL`                       | yes      | `postgresql+psycopg://user:pass@host:5432/dbname`                               |
| `CORS_ORIGINS`                       | no       | Only needed if a browser calls the API directly instead of through the proxy.   |
| `JWT_ACCESS_TOKEN_EXPIRES_MINUTES`   | no       | Default `30`.                                                                   |
| `FLASK_DEBUG`                        | no       | Leave unset (or `0`) in production.                                             |
| `PORT`                               | set by host | `run.py` reads it; gunicorn binds with `--bind 0.0.0.0:$PORT`.                |

Generate secrets with:

```bash
python -c "import secrets; print(secrets.token_hex(32))"
```

Never commit `.env` (it is already git-ignored).

### Release steps

```bash
cd backend
python -m venv .venv && source .venv/bin/activate    # Windows: .venv\Scripts\activate
pip install -r requirements.txt
flask db upgrade                                    # applies the Alembic migration (PostgreSQL)
flask create-admin --email ops@example.edu --name "Campus Ops" --password 'a-long-password-12+'
```

`create-admin` still prompts interactively when the flags are omitted.

### Start command

```bash
gunicorn --bind 0.0.0.0:${PORT:-8000} --workers 2 --timeout 60 run:app
```

### Health check

```bash
curl -i https://your-api.example.com/api/health
# expect: 200 {"database":"connected","status":"ok"}
```

Anything else (503) means the API is up but the database is not reachable.

## 1b. Backend on Render (the repo ships a blueprint)

[render.yaml](render.yaml) describes both resources, so Render creates them from
the repository:

- `signalloop-api` — Python web service, `rootDir: backend`, build
  `pip install -r requirements.txt`, start
  `flask --app run.py db upgrade && gunicorn --bind 0.0.0.0:$PORT --workers 2 --timeout 60 run:app`,
  health check `/api/health`, `autoDeploy` on push.
- `signalloop-db` — PostgreSQL, `connectionString` injected as `DATABASE_URL`.
- `SECRET_KEY` / `JWT_SECRET_KEY` are generated by Render (never committed), and
  `FLASK_DEBUG=0`, so the startup secret guard passes.

Steps:

1. Push this repository to GitHub (the remote is
   `https://github.com/Innovatoramaizn/Team-Byteforce-.git`).
2. Render → **New → Blueprint** → select that repo. Render reads `render.yaml`
   and creates the service and the database.
3. When it is live, create the campus admin once: Render dashboard →
   `signalloop-api` → **Shell**:

   ```bash
   flask --app run.py create-admin --email ops@example.edu --name "Campus Ops" --password 'a-long-password-12+'
   ```

4. Copy the service URL (e.g. `https://signalloop-api-xxxx.onrender.com`) into
   `vercel.json`'s rewrite `destination` (origin only, no `/api`), then redeploy
   the site.

Things Render's free tier forces on you:

- The free **PostgreSQL instance expires 30 days after creation** (1 GB, no
  backups) — upgrade it before that or the data is deleted.
- The free **web service spins down after 15 minutes** without traffic; the next
  request takes ~1 minute to wake it, so the first sign-in after idle feels slow.
- The disk is **ephemeral**: photo uploads land in `backend/instance/` and are
  lost on every redeploy. Attach a Render disk if photos must survive.
- Migrations run at process start (free plans have no pre-deploy hook), so a bad
  migration stops the boot and the health check fails loudly.

### Notes

- The database must be PostgreSQL: the migration uses `JSONB`. SQLite only works
  for throwaway local experiments (`db.create_all()`), not migrations.
- Photo uploads are written to `backend/instance/incident_uploads/`; give the
  service a persistent disk if you care about photos surviving redeploys.
- Requests are capped at 5 MB (`MAX_CONTENT_LENGTH`).
- The API is not rate-limited or token-revoking yet — put it behind your host's
  TLS terminator and, if exposed publicly, a rate limiter.

## 2. Frontend (Freebuff Sites)

```bash
npm run build        # copies index.html, src/ and assets/ into dist/
```

- Deploy manifest: `site.manifest.json` (Worker entrypoint `worker.js`, assets
  from `./dist`).
- Set the site variable **`API_ORIGIN`** to the backend origin **without** a
  path, e.g. `https://signalloop-api.example.com`. Without it the Worker answers
  `/api/*` with `502 api_not_configured`.
- The Worker serves the static site for everything else and passes `Authorization`
  headers through untouched.

### If you cannot use the proxy

Set `src/config.js`:

```js
window.SIGNALLOOP_CONFIG = { apiBase: "https://signalloop-api.example.com/api" };
```

and add your site origin (e.g. `https://your-site.example.com`) to the backend's
`CORS_ORIGINS`.

## 2b. Frontend on Vercel (alternative to Freebuff Sites)

[vercel.json](vercel.json) points Vercel at the same build and does the same
proxy with rewrites instead of a Worker:

- `buildCommand`: `npm run build` → `dist/`
- `outputDirectory`: `dist`
- `rewrites`: `/api/:path*` → `https://your-api-origin/api/:path*`

One thing has to be edited before it works: replace `signalloop-api.example.com`
in the `destination` with your real backend origin (no `/api` in front — the
rewrite keeps the path). Every change to `vercel.json` needs a redeploy.

Deploy:

```bash
npx vercel login          # once per machine
npx vercel deploy --prod   # production; drop --prod for a preview URL
```

Connecting the Git repository in the Vercel dashboard works too — the build
command and output directory are read from `vercel.json` automatically.

`worker.js` and `site.manifest.json` are only for Freebuff Sites; Vercel serves
`dist/` directly and never runs the Worker. If you prefer no proxy at all, delete
the `rewrites` entry, set `src/config.js` `apiBase`, and add the Vercel domain to
the backend's `CORS_ORIGINS`.

## 3. Local development

```bash
# terminal 1 — API on port 5000 (PostgreSQL, or SQLite for a quick look)
cd backend
cp .env.example .env                      # then edit it
flask db upgrade
flask --app run.py run --debug --port 5000

# terminal 2 — front end on port 3000 (already in the backend's CORS allowlist)
npm start                                 # npx serve . -l 3000
```

`src/api.js` picks the API location automatically:

- `localhost` / `127.0.0.1` → `http://127.0.0.1:5000/api`
- anywhere else → `/api` (the Worker proxy)

`wrangler.test.jsonc` exists only to exercise the Worker locally:

```bash
npx --yes wrangler dev --config wrangler.test.jsonc --port 8787
```

## 4. Verification checklist

- [ ] `GET /api/health` returns `{"status":"ok","database":"connected"}`
- [ ] Register a student, sign out, sign in again
- [ ] Submit an incident and see it on the student home screen after a reload
- [ ] Sign in as an admin (created with `flask create-admin`), open the queue,
      set a status/department, and confirm the history entry
- [ ] A student cannot see another student's report (server-side, not just hidden in the UI)
- [ ] Requests without a token return 401 and the UI returns you to sign-in
